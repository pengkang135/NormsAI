# 属性表头修复方案

## 核心原则

脚本是执行工具，**AI对照原始PDF检验是修复正确性的唯一保障**。脚本基于启发式规则推断，可能误判；只有AI逐页比对原始PDF才能确认修复正确。

## 修复流程

```
AI抽样诊断 → 编写脚本 → AI小范围测试(3-5页) → 全量运行 → AI抽样验证(20+页) → 重建DB
                     ↑________ 发现误伤/越界/遗漏则修正脚本 _________↓
```

## 诊断方法

打开提取的JSON，逐个属性比对原始PDF的表头：

```
提取的JSON (P205修复前):                    对照PDF确认真值:
  {name:"属性1", values:["一","","","一","",""]}  ─┐
  {name:"属性2", values:["二","","","二","",""]}   ├─ 实为"土壤类别"
  {name:"属性3", values:["三","","","三","",""]}  ─┘
  {name:"属性4", values:["26","", "","30","",""]} ── 实为"桩长(m)"

修复后:
  {name:"桩长(m)",   values:["26","26","26","30","30","30"]}
  {name:"土壤类别",  values:["一","二","三","一","二","三"]}
```

## 修复脚本

`temp/scripts/fix_extracted_attrs.py`

### 处理逻辑

对每个页面的 `attr_dimensions`，逐属性分类 → 决定处理方式：

| 属性值特征 | 分类 | 处理 |
|-----------|------|------|
| 全是纯单位/注释（艘班、台班、注：...） | `garbage` | **删除** |
| 含标签文本（桩长（m）、管径(mm)...） + 含数值 | `mixed` | 标签→属性名，清标签后密集化 |
| 仅含标签文本 | `label` | 暂存，作为下一个数值属性的名称 |
| 中文数字（一/二/三） | `chinese_num` | 密集化，同时**检测分组边界** |
| 纯数字或数字+单位 | `numeric` | 密集化填充 |
| 中文分类名（一般土方、冻土） | `category` | 密集化填充 |

### 三个关键算法

**分组边界检测** — 防止密集化时值跨组越界。利用中文数字列的重复模式：
```
土壤类别: [一, 二, 三, 一, 二, 三]
           ↑         ↑
           组1        组2 ← "一"重复出现的位置=边界

桩长(m): ["26","26","26","30","30","30"]  ← 位置3为边界，26不越界
```

**表头/数据列边界** — 续表（`continued_table`）中前几个属性是表头，后面是密集费用数据列。检测密度突变点，边界之后的属性原样保留不修改。

**已有语义名保护** — 不覆盖AI已正确识别的属性名：
```python
if name.startswith('属性') or not name:
    new_name = extracted_label  # 用标签
else:
    new_name = name  # 保留（如"水深"不被改为"土壤类别"）
```

### 隐性问题：孤儿标签

当标签属性是该页唯一（或最后）属性时，脚本的 pend/later 机制失效——标签被暂存但永远无人消费，导致该属性被丢弃且名称丢失。

**特征**：`属性X` 的值数组中有标签文本（如"桩长（m）"），但没有后续数值属性来承接标签名。

**检测方法**：`python temp/scripts/fix_extracted_attrs.py <范围> --dry-run`，输出 `Skipped` 的页面逐一检查——如果值中含有标签文本但被跳过，说明是孤儿标签问题。

**修复**（v2）：循环结束时 flush 未被消费的 `pending_labels`，用提取的标签名创建对应属性。
