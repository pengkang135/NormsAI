## 1. 问题

CostSpread 批次 `20260928-01`（斯里兰卡 · Mireka 海景公寓及别墅项目成本测算表）已入库 513 条
斯里兰卡单价，但那只在报价库里；企业定额要用它做斯里兰卡基准价，得把它挂到人材机主数据
（`resource_master.sqlite`），并注册成一个**价格包**。

`db/CLAUDE.md` 已定好机制：**新增国家包 = 插一行 `price_pack` + 灌该 pack 的 `resource_price`，
不复制主数据**；`resource` / `price_quote` / `quote_match` 跨包共享。

## 3. 探查结论（决定了方案形态）

### 3.1 报价是"清单式长名称"，规则匹配几乎失效

513 条里参与匹配的 219 条，名称形如 `釉面哑光瓷砖-M6`、`C20卫生间台面（3BHK户型卫生间，尺寸950 × 500mm）`。
`plan/基价方案` 的规则层（exact_full / exact_name / contain）只命中 **22 条**，
按字符二元组 Jaccard≥0.5 只召回 **5 条**。所以本批改成「按 `nameHead` + 二元组重合系数检索候选 → 子代理裁决」。

### 3.2 主数据里没有"综合单价"类目 → 55% 的报价无处可挂

| 专业 | 条数 | 可否匹配 |
|---|---:|---|
| 间接费（临建、调遣） | 175 | ✗ |
| 专业分包（门窗、桩基、涂料） | 108 | ✗ |
| 材料 | 172 | ✓ |
| 机械 | 30 | ✓ |
| 人工（属地） | 11 | ✓（折三档） |
| 周转材料 | 6 | ✓ |

### 3.3 单位维度硬门槛会挡掉一批"真同物"

| 报价 | 资源 | 问题 |
|---|---|---|
| 木模板-150/200侧模 `m` | 木模板 `m2` | 跨维度（需 xfactor，本期不做） |
| 混凝土小型空心砌块 `m2` | 混凝土小型空心砌块 `m3` | 同上 |
| 挖掘机/塔吊/天泵 `台班` | 对应机械 `台` | 同上 |

本期**不做跨维度换算**（`plan/基价方案` 的 `expand_match.py` 才有），这些报价留在 `price_quote`。

### 4.3 一物多价的处理

同一资源被多条同物报价命中时（如 10 条踢脚线 → `地砖踢脚`、7 条通体砖 → `通体砖0.09m2以内`），
`price_lk.py` 取**中位数**（沿用 `price_from_quotes.select_price` 的口径），比"取第一条"更能代表兰卡水平。

## 5. 为什么 `lk_2026` 是 inactive

`src/price_api.py:_default_pack` 与 `src/export_norms.py` 都是
`SELECT pack FROM price_pack WHERE status='active' ORDER BY pack LIMIT 1`。

两个包同时 `active`，字典序会让默认从 `th_2026` 变成 `lk_2026`——
**定额导出会悄悄改用兰卡价**，而那是要给中国/泰国项目用的。所以：

- `lk_2026` 设 `status='inactive'`：价格库里仍可切换查看，全局默认仍是 `th_2026`
- 要把它设为全局默认，改 `common_lk.PACK_STATUS = 'active'` 重跑 `build_lk_quotes.py`，
  **但先改 `_default_pack` 的选包逻辑**（按 pack 名排序取第一条是个隐患，建议改成显式 `is_default` 或 config）

## 6. 已知缺口（不做，如实记录）

1. **报告层覆盖小**：52/13,987 个资源。用户选的是"先报价层"，无报价的资源一律留空，**没有编造数字**
2. **跨维度未做**：木模板侧模（m vs m2）、空心砌块（m2 vs m3）、机械（台班 vs 台）——需 `xfactor`，属 Phase 2
3. **专业分包/间接费不入主数据**：283 条只作报价留档。若日后要按"综合单价"套价，需要先扩主数据类目
4. **`_hierarchy` 里 40 条报价连候选都没有**（如 `市政用水服务费`、`清关费+当地运费`、`车棚区域`），本就不该有主数据对应物
5. **人工工种粒度未保留**（见 §4.1）
6. **前端价格库**：`status` 徽章会显示 inactive；若要让它成为可直接套价的包，需与前端确认切换入口

### 9.4 已知问题

1. **`cn_2026` 的无规格钢筋 = 0.725 CNY/kg**，疑似数据错误（正常约 3.5~4）。兰卡侧已有报价不受影响，但泰国/中国包值得复查。
2. **`cn_2026` 的 C20（312.62）低于 C15（459.36）**，基线倒挂。兰卡侧已用标号线性外推规避。
3. **材料大类系数 1.537 由 16 个锚点标定，锚点偏装修材料**（瓷砖、标识、地板），大宗材料（砂石、水泥、钢材）需按 `lk_top200_review.csv` 复核。
4. **专家定值（`MANUAL_CATEGORY`）**：钢材-钢筋 1.3（由兰卡钢筋报价反推，派生出的 φ10以外 0.743 USD/kg 与报价 0.736 吻合）；油料/能源水电/气体 1.0 为无锚点平价，**需要兰卡当地询价来替换**。
5. **【执行新增】同一产品在 `cn_2026` 里基线不一致，会把价差直接传下来**。实例：`水泥 32.5`（res5591）cn≈311 CNY/t → LK 70.4 USD/t，而 `水泥 32.5级`（res5592）cn≈840 CNY/t → LK 190.2 USD/t，差 2.7 倍；`水泥425`（res5595）181.1、`水泥 #42.5`（res5590）65.4。兰卡散装水泥实际约 137 USD/t（参照 CostSpread 内斯里兰卡保障房项目价格表 709 USD/t 为袋装零售口径），**低档明显偏低**。根因是 `resource_alias.src_Price` 的中位数取法，与已知的「无规格钢筋 0.725」同类；本期只记录不改。
6. 留空资源清单见 `temp/lk_unpriced.csv`（3,160 条 / 39,232 refs）。refs 最高的集中两类：艘班（机动艇 44kW 1052、拖轮 441kW 870、方驳吊机船组 30t 801…）与大宗/周转材料（干混砌筑砂浆 DM10 752、防水砂浆 1:3 707、井室盖板 625…）。

差异出在口径：Mireka 那份明确标了「**不含泵送费**」，市场表是商品混凝土供应价，两者不可比。

资源名匹配 `^C\d{2}$` 且单位为 m3 时，若存在市场表报价就只用市场表那套。
