# 前端增加「价格库」模块

> 状态：Phase 1~6 已执行，浏览器实机验证通过。
> 一次性迁移脚本在 `temp/scripts/`，常驻脚本在 `scripts/`。

## 1. 问题

`output/norms_browser.html` 目前只有一个视图：定额库。左侧选册/章，右侧看定额子目与消耗量。价格在这个视图里是**附属信息**——只以 `Consumption.cons_Price` 一列出现在消耗量明细里，看不到这个价从哪来、什么时候的、可靠不可靠，更看不到全库层面「哪些人材机有价、哪些没价」。

2026-08 做完泰国参考基价后，`db/resource_master.sqlite` 已经沉淀了完整的价格事实源与溯源链，但前端没有任何入口能看到它：

```
resource(13,981)  ──→ resource_price(10,191, 全 THB)  ──quote_ID──→ price_quote(13,421 条原始报价)
      │                      ↑                                              ↑
 各册 Consumption      tier/price_kind/source                    供应商/日期/国别/币种/含税/来源文件/专业
 (master_res_ID 100% 挂靠)                                              quote_match(11,728)
```

目标：加一个与定额库并列的**价格库**视图，用来回答三个问题——**有哪些价**、**哪些还没价**、**这个价可靠不可靠**——并把「价格包」做成可切换的维度，为将来换国家（越南包、印尼包）留出位置。

## 2. 探查结论（这些结论决定了方案形态）

### 2.1 覆盖率本身就是这个页面的主线

按册×类别统计（refs = 定额引用次数，口径见 `Content` 表）：

| 册 | 材料 | 机械 | 设备 | 主材 |
|---|---|---|---|---|
| A 建筑装饰 | 81.2% | 74.5% | — | — |
| B 通用安装 | 100% | 99.7% | **3.9%** | **15.8%** |
| C 市政园林 | 85.7% | 84.0% | 10.5% | **12.5%** |
| D 水运工程 | **25.4%** | **23.2%** | — | — |
| E 房屋修缮 | 100% | 100% | — | **11.7%** |

人工五级全部有价。无价但被定额引用的资源 **3,787 条 / 53,261 次引用**，可直接按 refs 排缺口优先级：

| refs | 资源 |
|---:|---|
| 1734 | 机械 汽车式起重机 8t 台班 |
| 1528 | 机械 干混砂浆搅拌机200L 台班 |
| 1052 | 机械 机动艇 44kW **艘班** |
| 980 | 材料 干混抹灰砂浆DP M10 m3 |
| 870 | 机械 拖轮 441kW **艘班** |

艘班是已知硬缺口（无源可补，见 `plan/基价方案/基价方案.md` 2.9）。

### 2.2 可靠度阶梯是现成的

`resource_price.tier` + `price_kind` 两列已经把来源可靠度分好了层：

| tier | price_kind | 行数 | 含义 |
|---|---|---:|---|
| T1 | quote | 41 | 泰国直采报价 |
| T2 | quote | 387 | 邻国报价（马来西亚/印尼/柬埔寨） |
| T3 | quote | 792 | 中国报价 |
| T4 | quote | 221 | 非洲报价（肯尼亚/斯里兰卡） |
| S | similar | 535 | 近重名资源对齐 |
| D | derived | 8,215 | 中国基线 × FX × 标定系数派生 |

「数据来源可靠不」这个问题，答案就是这张表——前端只要把 tier 做成可视徽章并支持筛选即可。

### 2.3 「项目名称」藏在 `price_quote.source_doc`

原始报价表 `price_quote`（13,421 条）没有独立的 project 列，但 `source_doc` 就是项目名载体：

```
2025年印尼OKI造纸厂项目价格表.xlsx
2025肯尼亚蒙巴萨大型高层住宅项目.xlsx
OUT2025-10吉隆坡半导体石英材料厂房建设项目 报价书 3.1价格表.xlsx
中国 长远锂电厂扩产项目分包合同单价.xlsx
```

字段填充率：`quote_date` 100% / `specialty` 100%（建筑装修 4902 / 机电设备 4598 / 劳务分包 1130 / 型钢 456 …）/ `source_doc` 90.8% / `features`（规格）86.5% / `supplier` 34.6% / `contact` 5.9%。

用户要的「名称、规格、单位、币种、时间、供应商、项目名称」全部可得，其中项目名走 `source_doc`。

### 2.4 配比材料与机械台班只有单价，没有组成

- **配比材料**（`kind_Code LIKE '06%'`）：A 67 / C 112 / E 82 条，B、D 无。每条只有一个单价，库里**没有配合比表**（查过 5 册与 refers/ 北京2012、2021，均无「配合比」章节或组成表）
- **机械台班**（`cons_Style = 5`）：泰国口径是租赁台月÷26 班折算、已含机上人工、不含燃料（燃料在定额中单列，见基价方案 2.5），**源头就是整租包干价，拆不出**折旧/检修/维护/安拆/人工/燃料分项

→ 本期两个模块只做价格清单 + 口径说明。组成明细是独立的数据工程，后续单独排期。

### 2.5 顺手要修的既有 bug

`src/export_norms.py:232` 的 `_load_price_meta()`：

```python
"SELECT res_ID, price_date, source FROM resource_price "
"WHERE country='泰国' AND currency='THB'"
```

`country` 存的是**报价来源国**（8,215 行是 `'中国'`，因为派生自中国基线），不是价格归属国。这个过滤实际只命中 **30 / 10,191** 行——综合单价表导出的「定价日期/来源」列几乎全空。加 `pack` 列后换成 `pack='th_2026'` 即修复。

## 3. 数据层改动

改前备份到 `db/backup/resource_master.sqlite.pre-pack-{时间戳}.bak`（已落）。

### 3.1 `resource_price` 加 `pack` 维度 ✅ 已执行

原 PK `(res_ID, country, currency, price_date)` 里 `country` 是报价来源国、不是包归属，撑不起「切换价格包」。重建表：

- 新增 `pack TEXT NOT NULL`，现有 10,191 行统一置为 `'th_2026'`
- PK 改为 `(res_ID, pack, price_date)`——一个包里一个资源在一个日期只有一个结论价
- `country` / `currency` 降为属性列，语义不变
- 其余 20 列（`tier`/`price_kind`/`source`/`fx_rate`/`unit_factor`/`src_*`/`supplier`/`remark`…）原样保留
- 加索引 `idx_price_pack (pack, res_ID)`

`resource` / `price_quote` / `quote_match` / `price_anchor` **不动**——资源主数据和原始报价跨包共享，只有定价结论分包。

脚本：`temp/scripts/migrate_price_pack.py`（幂等，重跑会跳过已迁移的表）。

### 3.2 `price_pack` 元数据表 ✅ 已执行

```sql
CREATE TABLE price_pack (
  pack TEXT PRIMARY KEY,
  name TEXT, name_EN TEXT,
  country TEXT, currency TEXT,
  fx_json TEXT,          -- {"CNY": 5.0}：记账币 → 其他币换算
  cutoff_date TEXT,
  status TEXT,           -- active | draft | archived
  note TEXT              -- 口径说明，前端在包切换器下方展示
);
```

已种一行 `th_2026` / 泰国参考基价 2026 / 泰国 / THB / `{"CNY":5.0}` / 2026-12-31 / active，note 写明标定系数、台班口径、留空规则。

新增国家包 = 插一行 `price_pack` + 往 `resource_price` 灌该 pack 的定价结论，不需要复制资源主数据和原始报价。

### 3.3 `resource_usage` 聚合表 + 常驻脚本

价格库要按册导航、要显示引用次数，跨 5 库 ATTACH 聚合太慢。预计算一张表（16,912 行 / 13,780 个资源，
= 五册在用 `Consumption` 条目数 2772+4050+5185+708+4197；主数据里另有 201 条不被任何册引用，不进此表）：

```sql
CREATE TABLE resource_usage (
  res_ID INTEGER, vol TEXT, cons_ID INTEGER,
  cons_Style INTEGER, kind_Code TEXT,
  cons_Name TEXT, cons_Standard TEXT, cons_Units TEXT,   -- 该册的原始写法
  refs INTEGER,                                          -- 该册 Content 引用次数
  PRIMARY KEY (res_ID, vol, cons_ID)
);
```

新建 `scripts/build_resource_usage.py`，从 5 册的 `Consumption LEFT JOIN Content` 生成。要点：

- `cons_Style` / `kind_Code` 取**分册视角**的值——同一资源在 A 册是材料、在 B 册可能是主材，分册导航要按册内分类走
- 各册数据更新后需重跑；脚本幂等（先 DELETE 再插）
- `Consumption.master_res_ID` 五册 100% 挂靠，无需空值兜底

有了它，全部价格库查询单库完成，「以主数据为准、分册视图是子集」的口径就是 `WHERE vol='A'`。

### 3.4 修 `_load_price_meta`

`src/export_norms.py:232` 过滤条件 `country='泰国' AND currency='THB'` → 按 `price_pack` 里 `status='active'` 的包取。

## 4. 后端 API

`start.py` 新增，全部只读 `resource_master.sqlite`。沿用现有 `get_db()` / `send_json()` / `do_GET` 分支写法，新增 `get_price_db()`（固定指向 `DB_DIR/'resource_master.sqlite'`，`mode=ro`）。所有端点接 `pack` 参数，缺省取 `status='active'` 的第一个包。

| 端点 | 参数 | 返回 |
|---|---|---|
| `/api/price/packs` | — | 包列表 + 默认包 |
| `/api/price/index` | `pack` | 侧栏树：5 册（每册按类别分子节点）+ 配比材料 / 机械台班 / 机电主材 + 覆盖总览；每节点带 `total / priced / coverage` |
| `/api/price/list` | `pack, scope, vol, cls, priced, tier, q, limit, offset` | 资源行：res_ID / res_Code / 类别 / 名称+规格+单位（中英）/ 价(THB) / 价(CNY) / tier / price_kind / price_date / refs / 所属册 |
| `/api/price/detail` | `pack, res_ID` | 单资源全量（见 4.2） |
| `/api/price/coverage` | `pack` | 册×类别覆盖矩阵、tier 分布、无价缺口 top-N |
| `/api/price/gap` | `pack, vol, cls, limit` | 缺口清单 + 候选报价 |
| `/api/price/export` (POST) | `view, pack, scope, vol, cls, priced, tier, q` | xlsx 下载，见 §4.3 |

| `machine` | `cons_Style = 5` | A 220 / B 374 / C 699 / D 314 / E 1 |
| `me_main` | `cons_Style IN (6,7)` | B 1503 / C 332 / E 563 |

### 4.2 `/api/price/detail` 返回结构

用户「看到完整的价格信息，包括名称、规格、单位、币种、时间、供应商、项目名称等来源信息」的落点：

```
{
  resource: { res_ID, res_Code, res_Class_Name, res_Family,
              res_Name, res_Standard, res_Unit,
              res_Name_EN, res_Standard_EN, res_Unit_EN,
              res_Status, src_vols, alias_count, content_refs },

  price:    { pack, price, currency, price_excl, price_incl, tax,
              price_date, tier, price_kind, source, remark,
              src_country, src_currency, src_price, src_unit,
              fx_rate, unit_factor, supplier, source_doc },      -- 台账价（结论）

  quotes:   [ { quote_ID, name, name_en, features, unit, std_unit, unit_factor,
                country, currency, price_incl, price_excl, tax,
                quote_date, supplier, contact, phone, address,
                source_doc, specialty, tier,
                match_type, confidence } ],                      -- 候选报价，quote_match 关联

  aliases:  [ { vol, cons_ID, cons_Name, cons_Standard, cons_Units,
                src_Price, unit_factor, match_type, refs } ],    -- 各册原始写法 + 本册引用次数

  norms:    [ { vol, norm_Code, norm_Name, norm_Units, cont_Amount } ]  -- 引用该资源的定额子目 top 50
}
```

`aliases` 走 `resource_alias`（A 册 2,772 个在用 cons_ID 全部命中；多出的 1,315 条是去重前的历史别名，按 `resource_usage` 过滤掉）。`norms` 按 vol ATTACH 对应册库单查——只在详情面板触发，不影响列表性能。

### 4.3 Excel 导出（`src/export_price.py`）

每个价格库页面右上都有「导出 Excel」，按所在页面导对应形态。`view` 由前端 `exportViewKind()` 判定：

| view | 触发页面 | 工作表 |
|---|---|---|
| `list` | 分册 / 配比材料 / 机械台班 / 机电主材 / 全部人材机 | 导出说明 + 人材机价格清单（25 列，含中英名称规格单位、含税/不含税、来源等级与类型、原始报价与汇率单位换算、供应商、来源文件/项目、推导依据、引用次数、所属册） |
| `coverage` | 覆盖总览 | 导出说明 + 覆盖矩阵（册×类别，按覆盖率分三档着色）+ 未定价缺口（top 500） |
| `gap` | 机电主材缺口撮合 | 导出说明 + 缺口询价表（缺口信息合并单元格 + 候选报价逐行，含单位是否一致、相似度、供应商、项目、来源文件） |

三条约束：

- **导的是筛选条件下的全量**，不受列表 600 条显示上限影响。`api_list` 与导出共用
  `price_api.build_list_query()`，保证导出的就是屏幕上那批的完整版
- **每份带「导出说明」页**：价格包口径（国别/币种/汇率/截止日期/note）+ 本次筛选条件 + 统计 +
  来源等级含义。脱离前端后仍能说清这批数怎么来的
- **缺口询价表上限 200 条**（撮合每条约 16ms，全量 2,097 条要 34s）。截断量在说明页和前端提示里
  明确报出「本范围共 N 条，导出前 M 条，另有 K 条未包含」，不做静默截断

筛选条件进文件名（`价格库_B册 通用安装_设备_仅无价_价格清单.xlsx`），避免同一页面筛选前后互相覆盖。

## 9. 实施中的偏差与补充发现

**撮合不按 `specialty` 预筛**。原计划用 `specialty LIKE '%机电%'`（4,604 条）作候选池，实测该列标注不可靠——
`机电设备` 里混着 UPVC 排水管与履带挖掘机。改为全池 13,421 条搜索，两段式匹配
（字符集粗筛 top40 → `SequenceMatcher` 顺序敏感重排 → 阈值 0.34 截断）。

**B 册工艺设备在全库确实无报价**。球罐 / 反应器 / 输送机 / 换热器 / 配电柜关键词在 13,421 条报价里命中 **0**。
撮合返回空候选是正确答案，不靠降阈值制造假阳性。40 条缺口里 19 条有候选、21 条标「全库无对应报价，需外部询价」。

**名称相似但单位不符是主要假阳性**（接地编织铜线 m ↔ 编织袋 个、高压碳钢对焊管件 个 ↔ 钢管和扣件 kg）。
不靠分数掩盖，候选行上直接标「单位不符」，由人判断。

**项目名有两个载体**。原计划只认 `source_doc`，实测 43 条 T1 直采报价把项目塞在 `features` 里
（`project=Evolution Data Center | location=Bangkok Bangna | sheet=…`），且这 43 条正是 `country` 损坏成
字面 `'??'` 的那批。前端加显示层解析：抽出 `project=`/`location=` 加粗展示，`'??'` 渲染成空而不是假国别。
不改数据。

**列表页的「有价」数必须走全量聚合**。首版用页内 `items.filter(...)` 计数，600 条 LIMIT 下机械台班显示
「有价 226」而侧栏是 862/1236。这个页面的主线就是覆盖率，分页不能把它算错——`api_list` 改为返回
筛选条件下的 `priced` / `refs` 全量值。

**`body` 要改 `flex-direction: column`**。加 topbar 后忘了改方向，topbar 与 workspace 变成并排，
被 `overflow:hidden` 遮住不易察觉。另给 `.main` / `.workspace` 补 `min-width: 0`——flex 子项默认不收缩到
内容宽度以下，宽表会把整页撑出横向滚动条。修后宽表只在 `.data-table-wrap` 内滚动。

**已知既有限制（非本次引入）**：`start.py` 用单线程 `TCPServer`，浏览器 keep-alive 连接会占住服务，
另开 HTTP 请求（如 curl 测导出）会挂起。价格库各端点均 <0.25s，实际使用无感知；
要并发需换 `ThreadingTCPServer`。
