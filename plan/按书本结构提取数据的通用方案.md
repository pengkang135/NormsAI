# 按定额书本结构提取数据的通用方案

## 问题

定额PDF是一整套结构化文档，不仅包含定额表格，还有目录、说明、页眉页脚、章节层级。无论PDF是文本型还是图片型（OCR），都需要按原书结构组织提取结果。

## 核心思路：结构与内容分离

```
                    文档结构层 (通用)
                   /                \
          文本型PDF内容提取      图片型PDF内容提取
         (PyMuPDF文本+坐标)      (OCR+坐标)
```

**结构层与内容提取方式无关** — 目录解析、章节边界检测、页面分类等逻辑对两种PDF类型通用。只有底层的内容提取方式不同。

## 文档结构模型

一本定额书 = 以下要素的组合：

```
Document (1本)
├── 封面/版权页 (cover)
├── 公告/修订说明 (notice)
├── 目录 (toc, 多页)
├── 总说明 (general_instruction)
├── Chapter 1 (章)
│   ├── 章标题页 (chapter_title)
│   ├── 章说明 (section_intro)
│   ├── Section 1.1 (节)
│   │   ├── 节标题/说明 (section_intro)
│   │   └── 定额表组 (norms_table_group)
│   │       ├── 定额表页1 (norms_table, 含完整表头)
│   │       ├── 定额表页2 (continued_table, 续表)
│   │       └── ...
│   ├── Section 1.2
│   │   └── ...
│   └── ...
├── Chapter 2
│   └── ...
├── ...
└── 附加说明 (appendix)
```

## 数据结构设计

### 结构索引 (structure.json)

这是核心输出，描述整本书的组织结构，与内容提取方式无关：

```json
{
  "document": {
    "title": "沿海港口水工建筑工程定额",
    "doc_number": "JTS/T 276-1-2019",
    "total_pages": 914
  },
  "page_map": {
    "1": {"type": "cover", "pdf_page": 1},
    "12": {"type": "toc", "internal_page": 1, "pdf_page": 12},
    "26": {"type": "general_instruction", "internal_page": 1, "chapter": "总说明", "pdf_page": 26},
    "30": {"type": "chapter_title", "internal_page": 5, "chapter": "第一章 土石方工程", "pdf_page": 30},
    "80": {"type": "norms_table", "internal_page": 55, "chapter": "第一章 土石方工程", "section": "第一节 陆上开挖工程", "subsection": "一般土方", "pdf_page": 80}
  },
  "chapters": [
    {
      "id": 1, "level": 1,
      "title": "第一章 土石方工程",
      "internal_start": 5, "internal_end": 173,
      "pdf_start": 30, "pdf_end": 198,
      "children": [
        {
          "id": 2, "level": 2,

          "internal_start": 18, "internal_end": 78,

            {"id": 3, "level": 3, "title": "一、一般土方", "codes": ["10001-10048"], "pdf_start": 43, "pdf_end": 51}

```

### 页面内容文件

每个页面的实际内容独立存储。格式因PDF类型而异，但都遵循统一的 `page_type` 约定：

**文本型PDF** → `output/md_jts/page_{XXXX}.md` (结构化Markdown)
**图片型PDF** → `output/md/page_{XXXX}.md` (OCR Markdown，已有的格式)

无论哪种，frontmatter统一：
```yaml
---
page: 80
type: norms_table            # 或 section_text / toc / continued_table 等
chapter: "第一章 土石方工程"
section: "第一节 陆上开挖工程"
subsection: "一般土方"
---
```

### 数据库表结构（复用现有 config.py DB_SCHEMA）

现有6张表已能覆盖完整文档结构，只需正确填充：

| 表 | 用途 | 填充时机 |
|----|------|---------|
| `document` | 文档元数据 | 结构解析后 |
| `chapter` | 四级章节层级(parent_id自引用) | 目录解析后 |
| `section_text` | 说明文字/目录/公告等文本页 | 文字页处理后 |
| `page_index` | 每页索引(page_type/chapter_id/table_id) | 全部页面分类后 |
| `norms_table` | 定额表元数据(关联chapter_id) | 定额表处理后 |
| `norms_item` | 定额条目(关联table_id) | 定额表处理后 |

## 通用处理流程

### Step 1: 页面类型分类

对每一页，判定其属于哪种类型。判定规则基于页面内容特征：

```
封面页   → 含"中华人民共和国行业标准"、"JTS"、"主编单位"等
公告页   → 含"公告"、"第X号"
目录页   → 含密集的"第X章"+"......"+页码 模式
说明页   → 含"总说明"或"说明"，无表格结构
章标题页 → 含"第X章"，页内文字<15行，无定额编号
定额表页 → 检测到>=3个5位定额编号(文本型) 或 有表格线(图片型)
续表页   → 页眉/顶部含"续表"
附录页   → 含"附加说明"或"附录"
空白页   → 几乎无文字
```

对文本型PDF：用PyMuPDF提取文本后按规则匹配
对图片型PDF：用OCR文本后按同样的规则匹配（增加了OCR噪声容忍）

### Step 2: 目录解析

目录页（通常在前20页内）是全书结构的权威来源：

1. 从目录页提取层级条目：章、节、子节、具体定额项目
2. 解析每个条目对应的**内部页码**
3. 建立 `内部页码 -> PDF页码` 的映射（从页脚 `- N -` 解析）
4. 构建完整的章节目录树

目录条目格式示例：
```
第一章 土石方工程 .............................................. (5)
  说明 ......................................................... (7)
  第一节 陆上开挖工程 ......................................... (18)
    一、一般土方 .............................................. (18)
      1. 人力挖一般土方和冻土 ................................. (18)
      2. 挖掘机挖装土方 ....................................... (20)
```

### Step 3: 结构映射

将每个定额表页关联到其在目录树中的位置：

```
目录页码 -> 内部页码 -> PDF页码 -> 确定章节归属
```

- 根据章节的 `internal_start`/`internal_end` 范围匹配每个定额表页
- 节说明页根据其内部页码归入对应章节
- 续表页继承前一页的章节归属

### Step 4: 数据入库

按 `document -> chapter -> page_index -> section_text / norms_table -> norms_item` 顺序写入。

关键：`page_index` 是中枢表，关联所有其他表。每个定额表/文字页都通过 `page_index.chapter_id` 和 `page_index.table_id` 定位。

## 输出物

### 文件清单

| 输出 | 说明 | 通用性 |
|------|------|--------|
| `structure.json` | 完整文档结构索引 | **通用**（不依赖PDF类型） |
| `output/md/page_{XXXX}.md` | 每页内容MD | 内容格式因PDF类型而异 |
| `output/norms_data.sqlite` | SQLite数据库 | **通用schema** |
| `output/norms_browser.html` | 前端浏览器 | **通用**（基于schema查询） |

### MD文件类型约定

所有MD文件统一使用 `type` frontmatter标记页面类型：

| type | 说明 |
|------|------|
| `cover` | 封面/版权 |
| `blank` | 空白页 |
| `notice` | 公告/修订说明 |
| `toc` | 目录页 |
| `general_instruction` | 总说明 |
| `chapter_title` | 章标题 |
| `section_intro` | 节说明/章说明 |
| `norms_table` | 定额表（首页，含完整表头） |
| `continued_table` | 定额续表 |
| `appendix` | 附录/附加说明 |

## 与现有代码的关系

- **文本型PDF**: 新方案直接适用，`extract_1d.py` -> `src/table_extractor.py`，全914页处理
- **图片型PDF**: 结构层复用同一套逻辑，内容层继续用OCR pipeline，输出统一MD格式
- **数据库**: 两种PDF类型共用同一套DB Schema，可在同一浏览器中查询
- **前端**: 增加章节导航树、文字页展示，两种PDF类型的查询结果统一展示

## 验证

1. `structure.json` 与PDF目录页人工对比，章节结构一致
2. 每页MD的 `chapter`/`section` 字段与所属章节的页码范围匹配
3. SQLite中 `chapter` 表的层级树与目录结构对应
4. 浏览器中可沿章->节->定额组的路径逐级导航到任意定额表
