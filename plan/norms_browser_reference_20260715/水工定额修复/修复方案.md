## 3 解析器方案

`temp/水工定额修复/scripts/parse_v2.py`。核心是**用 mergeCells 几何信息代替列号硬编码和词典猜测**。

### R1 锚点动态定位列
以 `定额编号` / `项目` / `单位` / `代码` 四个锚点单元格反查列号，数据区起始列 = `max(代码列, 定额编号列) + 1`。

### R2 编号 → 列区间按 merge 跨度切分
逐列扫锚点行，命中 5 位编号则取其 merge 区间 `[c1,c2]`，跳到 `c2+1` 继续。解决非连续数据列（p74 的 F, G-H, I, J, K, L）。

### R3 属性区：几何为主 + 词法辅助（修 D2）
每个属性行按 merge 切成若干"组"，每组覆盖一段连续编号：

- 组文本命中维度词特征**且**覆盖 ≥2 个编号 → 该段编号的属性标签（pending）
- 否则 → 该段编号的属性值，配上其 pending 标签

维度词特征 = 以量纲词结尾（`类别|级别|深度|吨位|斗容|桩长|…`），或以**纯单位括号**结尾（`（m）`、`（m³ )`、`（t）`）。
括号内含数字的一律不算 —— 否则 `水泥：土（10：90）` 这类配合比值会被误判为维度名。

标签可以只覆盖部分编号（p44 的 `土壤类别` 只覆盖 E-H，而 I/J 是纵向合并的独立子目）。

收尾再压缩**跨层纵向合并**：某编号在多层取到同一文本（表头单元格纵向跨了整个属性区，如 p44 的
`每增高 1m`），压缩为单层。这一步把 p44 从 5 层降到 ≤4 层，装得进 `attr_level1~4`。

### R4 注 / 调整小表切断（修 D1）
数据行扫描遇到以下任一即切断正表：

- 单元格以 `注：` 开头
- `cost_item == 基价` 且本表已出现过基价

切断点之后的内容全部归入新表 `adjustment_table` / `adjustment_row`，不进 `norms_item`。

### R5 续表三态合并（修 D7）
| 形态 | 判据 | 处理 |
|---|---|---|
| 纵向续表（重复表头，编号相同） | 首格 `续表` + 编号列表与上表全等 | 追加消耗量行，`sort_order` 续编 |
| 横向续表（重复表头，编号不同） | 首格 `续表` + 新编号 | 新表，继承表名/工程内容/单位，标记 `续表继承表名` |
| 无表头续表（182 页） | 无 `定额编号` 锚点但 A 列有连续序号 | 继承上表的编号→列区间映射，条目标 `data_quality='inherited_columns'` |

第三态是最高风险项（列布局可能在翻页时变化），已单独打标供校对 agent 重点复核。

选样时必须**沿续表链前后补全**，否则会出现假性"无基价"。

### R6 字符污染修复 + 复验（修 D6）
只在数字上下文替换 `l→1` / `O→0`，替换后按目标格式复验（编号 5 位 / 资源码 12 位 / 数值可 parse），
不通过则保留原值并标记待复核。每一处替换写入 `fix_log`（页/单元格/原值/改后/是否采纳）。

两个必须保留的例外：

- **ASCII 罗马数字** `I / II / III / IV`（本书用作土壤类别值）绝不能变成 `1 / 11 / 111 / 1V`
- 中文数字属性值（一/二/三）

单元格还要先清洗：去目录点线残留（`.\n    l0455`）、去竖排换行（`每增高\n1m`）。

### R7 未计价主材 + 资源代码（修 D4 D5）
`norms_item` 新增 `resource_code`（12 位）、`is_main_material`（源表括号数值）、`source_page`（修 D8）。

### R8 说明与附表通道（修 D3）
页面分类后分流。附表页判据是**首个非空单元格即 `附表 N`** —— 仅正文提及"附表 N"的说明页不算，
否则会把说明页误当附表灌进 `appendix_row`。附表跨续表页按 `page_from/page_to` 合并为一张。

## 5 多 Agent 校对流水线

**脚本判据只能保证内部一致，不能保证与源书一致。** 几何判据在以下场景仍会失手，必须靠交叉校对：

- 融合标签（`压实厚度 15cm` 拆成两层但无维度名）
- 标签只覆盖 1 个编号时退化为值
- 无表头续表页的列映射继承
- 字符修复后的值是否真是原书数值（`ll009.03` → `11009.03` 还是 `11009.03`？需人眼确认小数位）

采用 `pk-boq-ai-team` 的**换模型 = 独立信号**原则，不同环节不同模型把关。

```
[分片] export_review_md.py  (脚本, 0 token)
   |    89 个分片, 平均 6.5KB, 最大 10KB —— 源表原样 + 解析结果并排 + 校对清单
   |
   +--> [Reviewer A]  Sonnet   逐页比对, 只报差异        \
   |                                                      >  独立上下文, 互不可见
   +--> [Reviewer B]  Haiku    同页独立复核, 不看 A 结论  /
   |
   v
[汇总] apply_review.py         (脚本, 0 token)
   |    A/B 结论一致且 pass -> 归档
   |    分歧 或 任一方 fail  -> 送仲裁
   v
[Arbiter]  Opus   只看分歧页, 裁决并给出正确值
   |
   v
[回写] apply_review.py --arbitrate
   |
   +-- high 级问题 > 0 -> 修 parse_v2.py, 重建测试库, 重跑校对（回到分片）
   +-- high 级问题 = 0 -> 提交人工确认
```

### 分工与分片粒度

| 角色 | 模型 | 输入 | 产出 | 判据 |
|---|---|---|---|---|
| Reviewer A | Sonnet | 分片 8-10 页/agent | `findings/reviewer-a-*.json` | 逐格比对源表与解析结果，只报差异，不改数据 |
| Reviewer B | Haiku | 同上，独立派发 | `findings/reviewer-b-*.json` | 同上，不得看到 A 的结论 |
| Arbiter | Opus | 仅分歧页的分片 + 双方 findings | `findings/arbiter-*.json` | 裁决哪方正确，给出源书真值 |

约 89 页 × 2 = 178 个 reviewer 任务，按 10 页/agent 约 18 个 agent；仲裁按分歧量动态派发。

### 校对结论格式

```json
{"agent": "reviewer-a", "results": [
  {"page": 106, "verdict": "pass", "findings": []},
  {"page": 74, "verdict": "fail", "findings": [
    {"severity": "high", "field": "属性",
     "expected": "L1 应为 液压挖掘机斗容（m³）=0.8",
     "actual": "L1 = 0.8（标签丢失）", "note": "源表 F4:L4 是整宽标签行"}]}]}
```

放入 `temp/水工定额修复/data/review/findings/`，然后：

```bash
python apply_review.py           # 摄入 + 汇总分歧
python apply_review.py --diff    # 列出分歧明细（供仲裁 agent 使用）
python apply_review.py --arbitrate data/review/findings/arbiter-1.json
```

校对结论落 `review_finding` 表（agent / severity / field / expected / actual / verdict），可追溯。
